# NOTES_KB: venue knowledge pack + staff assistant

## What I built (new files only)
- `app/knowledge/venue_demo.json`: "Demo Hill Shrine", 46 entries (hours, route and the five queue_sim stops g1..g5, walking time/steps per stretch, facilities per stop, medical post, wheelchair/doli and how to request, cloak room, footwear, info counter, food, stay, transport, what to carry/wear, weather/night, rules, no payment/touts, elders/children/pregnant/disability, lost child, unwell, lost phone/slot, slots, walk-ins, rush mode, wait times, app languages/voice, contacts, FAQs). Each entry: id, topic, tags, triggers (English + Telugu/Tamil/Malayalam/Kannada/Hindi native script and romanised), short English answer, `where`, `simulated: true`. No deity names, no real temple.
- `app/knowledge/venue_stadium_demo.json` (8 entries, proves swapping), `pack_schema.json`, `README.md` ("How a shrine or venue loads its own pack"). The pack was generated by `/Users/arun/hackathon/festive/_tools/gen_pack.py` (rerun to regenerate; the JSON can also be edited by hand).
- `app/kb.py`: `search`, `facts_for(text, lang, position_stop_id=None)` (None when nothing scores above THRESHOLD=1.8), `topics()`, `pack_info()`, `venue_name()`. Scorer: tokens, stop words, exact / word-ending / consonant-skeleton / fuzzy matching, IDF weighting, topic-title boost, stop-name down-weighting, +15% for entries at the pilgrim's current stop. No services, no downloads. Pure stdlib.
- `app/addons_staff.py`: `router` with POST `/api/staff/ask`, GET `/api/staff/examples`, POST/GET `/api/staff/help`. Rules answer the 12 operations questions from live modules (queue_sim, slots, flags, volunteer, crash; lazy imports, every lookup tolerant); other questions go to `sarvam.chat_json` with a facts block (live facts plus kb pack facts) under the JSON contract {intent, reply, action, needs_confirmation}. Numbers in a model reply must appear in the facts or the question, else the reply becomes "I do not have that". Actions (book walk-in, report crowd, mark help handled) store a pending action per staff id for 120 s and ask a yes; yes (spoken, or `confirm:"yes"`) executes. Rush or slot-mode switching is refused: "The rush switch is approved through NudgeBee." Replies are English from rules, translated with `sarvam.translate`, spoken through `directions.speak` (shares the TTS cache).
- `app/addons_ui/staff_ask.html` + `staff_ask.js`: one "Ask anything" button (tap, speak, tap), cycling examples, reply text + audio, Yes/No buttons for confirmations, typed fallback. CSS vars only, `window.StaffAsk` is the only global.
- `app/tests/test_kb_staff.py`: 48 tests, all mocked. 25 pilgrim questions (English, romanised and native Telugu, Malayalam, Hindi), 5 unknowns return None, stadium pack swap, 12 staff questions, 3 actions with confirmation, rush refusal, number validation, model-down fallback, endpoints.

## Integration (integrator)
1. Pilgrim assistant hook, in `app/assistant.py` where the facts block is built (2 lines):
   ```python
   import kb
   block = kb.facts_for(text, lang, position_stop_id)   # None => no pack fact matched
   ```
   Append `block` to the facts and keep the instruction "answer only from these facts; if there are none, say you do not know and point to the information counter". Use `kb.topics()` for a "you can ask about" chip list. Optional: when the assistant detects a call for help, call `addons_staff.add_help(stop, text, uid)` so volunteers see it in "any pilgrim needing help".
2. main.py: `import addons_staff` is not needed if the `_mount` helper is used; otherwise `from addons_staff import router as staff_router` and `app.include_router(staff_router)`. With the existing mount helper: `_mount("addons_staff")`.
3. Staff screen (`app/static/volunteer.html`): paste the `<section id="staff-ask">...</section>` from `app/addons_ui/staff_ask.html` where you want it (its `<style>` is inside), load `<script src="/static/addons_ui/staff_ask.js">` (copy or serve the file), then `StaffAsk.init(document.getElementById('staff-ask'), {lang: () => 'ml', staffId: 'volunteer'})`. Use `lang: () => 'en'` for English.
4. Env: `VENUE_PACK` = pack name in `app/knowledge` (default `venue_demo`) or an absolute path. Needs the usual `SARVAM_API_KEY`. No new Python packages.

## Not verified / caveats
- Microphone recording path in `staff_ask.js` was syntax-checked only, not run in a browser; the staff audio STT path is covered by a mocked test, not a real call.
- "Since when" for rush uses the crash marker's start time while a rush runs, else the moment the staff assistant first saw rush on (in-memory).
- "Any pilgrim needing help" reads an in-memory list fed by `add_help` / `POST /api/staff/help`; nothing in the existing code raises help requests yet, so it says none until the assistant or UI calls it. Lost on restart.
- The NudgeBee answer shows `volunteer.public()` root cause and fix; it says quiet when no incident has happened.
- Matching is keyword and fuzzy: for unusual phrasing the model gets the top 3 entries and decides. Romanised Tamil/Telugu coverage is good for the common words, not exhaustive.
- The pack's times, distances and counts are invented demo values (all marked simulated).
